# Как писать курсы

Курс — это данные. Лекция описывается деревом блоков, каждый блок ссылается на
компонент по строке `type`, а платформа берёт на себя отрисовку, валидацию,
оценку времени, прогресс и навигацию.

Главное следствие: **ошибка в материале ловится тестами, а не читателем.**
`npm test` проверяет, что все параметры блоков валидны, все ссылки разрешаются,
все вопросы решаемы, а спираль остаётся спиралью.

---

## 1. Структура

```
Course              курс
 └─ Module          тематический раздел, задаёт порядок чтения
     └─ Topic       понятие («обратная связь»)
         └─ Level   тот же вопрос на большей глубине: 1 → 2 → 3
             ├─ Lecture     дерево блоков
             └─ Assessment  проверка уровня
```

Тема живёт в отдельном файле в `src/courses/<курс>/topics/`, курс собирается в
`src/courses/<курс>/index.ts`, каталог — в `src/courses/index.ts`.

## 2. Спираль

Платформа сама строит порядок изучения: сначала **все** темы на уровне 1, затем
все на уровне 2 и так далее. Автору нужно только заполнить два поля.

```ts
{
  level: 2,
  inherits: ['feedback@1', 'variety@1'],   // что этот уровень уже предполагает
  references: [
    { kind: 'prereq',      target: 'feedback@1' },
    { kind: 'deepens',     target: 'feedback@1' },
    { kind: 'foreshadows', target: 'stability@1', note: 'зачем это понадобится' },
    { kind: 'seeAlso',     target: 'other-course/topic@1' },
    { kind: 'external',    target: 'https://…', label: 'Ashby, 1956' },
  ],
}
```

- `inherits` собирает цели предков транзитивно; блок `recap` выводит их
  автоматически, а страница уровня показывает раздел «Опирается на».
- `references` проверяются на существование цели. Ссылка на несуществующий
  уровень — падение теста.
- Формат цели: `topicId@N` внутри курса, `courseId/topicId@N` между курсами.

Зависимости между темами задаются на уровне темы:

```ts
{ id: 'control', prerequisites: ['feedback'], levels: [...] }
```

## 3. Блоки

```ts
{ id: 'lead', type: 'prose', props: { text: '…', lead: true } }
```

`id` уникален внутри лекции и участвует в учёте прогресса — менять его у уже
опубликованного блока значит обнулить отметку о его прохождении.

### Текст и структура

| type | назначение |
| --- | --- |
| `prose` | абзац; `lead: true` — вводный, крупнее |
| `heading` | заголовок, `level` 2–4 |
| `list` | список, `ordered` для нумерованного |
| `callout` | врезка: `idea`, `history`, `warning`, `paradox`, `note` |
| `key-idea` | главная мысль раздела |
| `definition` | термин + оригинал + пояснение |
| `quote` | цитата с автором и источником |
| `formula` | формула с расшифровкой каждого символа |
| `steps` | нумерованная последовательность |
| `timeline` | хронология |
| `compare` | 2–3 колонки сравнения |
| `table` | таблица с подписью |
| `details` | сворачиваемое углубление |
| `exercise` | задание на размышление со скрытым разбором |
| `columns` | раскладка в колонки (принимает дочерние блоки) |

### Связанные с курсом

| type | назначение |
| --- | --- |
| `recap` | автоматическая сводка по `inherits` |
| `references` | автоматический список ссылок уровня |
| `checkpoint` | мини-проверка по ходу лекции, идёт в прогресс |

### Интерактивные

| type | что делает |
| --- | --- |
| `sim.control-loop` | контур с ПИД, запаздыванием, шумом и возмущением |
| `diagram.feedback-loop` | тактильная схема контура с пояснениями |
| `builder.control-loop` | сборка контура из блоков с разбором ошибок |
| `game.requisite-variety` | игра в закон Эшби |
| `game.black-box` | определение скрытого механизма зондированием |
| `viz.variety-explosion` | комбинаторный рост числа состояний |
| `viz.phase-plane` | фазовый портрет: три режима устойчивости |
| `sim.entropy` | энтропия и оптимальные коды |
| `sim.channel` | канал с шумом и помехоустойчивое кодирование |
| `sim.automaton` | элементарные клеточные автоматы |
| `sim.life` | «Жизнь» Конвея |
| `three.phase-space` | 3D: аттрактор Лоренца |
| `three.landscape` | 3D: ландшафт устойчивости |

Точный набор параметров каждого блока всегда доступен в приложении на странице
**«Компоненты»** (`/#/blocks`) — он берётся из схемы, а не из документации, и
поэтому не устаревает.

## 4. Разметка внутри текста

```
**жирный**            выделение
*курсив*              второстепенное выделение
`код`                 буквальное
[[термин|пояснение]]  термин с подсказкой при наведении
[текст](https://…)    ссылка
```

Всё, что не разобралось, остаётся текстом: `2 * 3` не превратится в курсив.

## 5. Проверки

```ts
assessment: {
  id: 'feedback-1-quiz',
  passingScore: 0.7,             // по умолчанию 0.7
  questions: [ … ],
}
```

Типы вопросов:

| type | ответ учащегося | частичный балл |
| --- | --- | --- |
| `choice.single` | индекс варианта | нет |
| `choice.multi` | массив индексов | да, со штрафом за лишние |
| `numeric` | число с допуском | нет |
| `order` | порядок элементов | да, по доле верных пар |
| `match` | сопоставление пар | да, по доле пар |
| `text.short` | строка из списка принимаемых | нет |
| `goal` | результат работы с виджетом | да, по достигнутому баллу |

`difficulty` (1–3) работает как вес вопроса. `concepts` попадают в список
слабых мест учащегося. Практическое задание описывается так:

```ts
{
  id: 'q4', type: 'goal', difficulty: 3,
  prompt: 'Настройте контур так, чтобы качество превысило 90%.',
  props: {
    widget: 'sim.control-loop',
    threshold: 0.9,
    widgetProps: { controls: ['kp', 'ki'], goal: { text: '…', minScore: 0.9 } },
  },
}
```

## 6. Требования к материалу

Тесты в `src/courses/courses.test.ts` намеренно жёсткие — они кодируют
редакционный стандарт, а не только техническую корректность:

- не меньше трёх целей обучения на уровень;
- аннотация длиннее 60 знаков, обязательная оценка времени;
- **не меньше 3500 знаков текста на уровень** — материал, а не пара абзацев
  перед квизом;
- хотя бы один интерактивный блок на уровень;
- у каждого уровня выше первого есть `inherits`;
- более половины уровней перекрёстно ссылаются на другие;
- каждый интерактивный компонент используется в курсе хотя бы раз;
- эталонные ответы дают ровно 100%, пустая работа — 0%;
- варианты внутри вопроса не повторяются, индексы верных ответов существуют.

Проверить материал: `npm test -- src/courses`. В режиме разработки все проблемы
курса дополнительно печатаются в консоль браузера при запуске.

## 7. Добавить курс

1. Создайте `src/courses/<id>/topics/*.ts` и `src/courses/<id>/index.ts`.
2. Добавьте курс в массив в `src/courses/index.ts`.
3. Запустите `npm test` — граф проверит связность, а редакционные тесты
   подскажут, чего не хватает.

Ссылаться на уровни соседнего курса можно сразу: `references` и `inherits`
понимают форму `courseId/topicId@N`, и граф свяжет курсы между собой.
